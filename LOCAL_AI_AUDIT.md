# Локальный модуль: архитектура и проверка

Исторический отчёт словарной версии. Текущие дополнения: HYBRID_AI_AUDIT.md и GOOGLE_TERM_AUDIT.md.

База изменений: fdaeda1fca9d1d29c73cf02ca8a8fbcb4831dbbd.
Рабочая ветка: fix/library-audit-and-document-safety. Main не изменяется.

## Сначала изучено существующее

Сохранены LiveSpelling, FavoritesPanel, AdaptiveMemory, FragmentGuard, DOCX/TXT IO,
локальное раскрытие сокращений, браузерный Яндекс Редактор и исходные папки библиотеки.
Действующего клиента внешней генеративной службы в исходной версии уже нет;
удалены оставшиеся неиспользуемые промпты и устаревшие упоминания.

## Выбор компонентов

| Компонент | Решение |
|---|---|
| RapidFuzz 3.12.2 (MIT) | Уже присутствует; расстояние Дамерау—Левенштейна и нечёткий поиск выполняются нативным CPU-кодом. |
| Hunspell/Spylls 0.1.7 (MIT, словарь BSD-style) | Сохранён для русских словоформ и ручной F7-проверки, один словарь на процесс. |
| SymSpell | Не добавлен: для небольшого медицинского индекса второй словарь и индекс удалений дублировали бы подбор кандидатов. Отдельный сравнительный бенчмарк пакета не проводился. |
| Pymorphy3 | Не добавлен в обязательную поставку. Hunspell проверяет словоформы; поиск использует кэшированные консервативные основы. Полного синтаксического/морфологического анализатора нет. |
| SQLite + n-граммы | Подтверждённые исправления, слова, контексты из двух слов и продолжения из 1–3 слов. Статистика хранится отдельно от избранного. |
| LLM, GPU, удалённый API | Не требуются и не добавлены. |

Новых бинарных зависимостей нет. Сравнение выше архитектурное: не заявляется,
что неустановленные библиотеки были измерены или что правила заменяют полный
лингвистический анализ.

## Новое поведение

- Коррекции: перестановки/пропуски/лишние буквы, частота, ближайшие соседи,
  анатомическая область, подтверждённый выбор; распознаётся однозначная неверная
  клавиатурная раскладка. Изменение текста только по выбору врача.
- Дополняются слова и проверенные фразы; частично набранное слово допускает опечатку.
  Enter не принимает подсказку. Tab и мышь поддерживаются. Список только сверху;
  при нехватке места он скрывается до показа.
- Активная орфография обрабатывает изменённые абзацы в единственном worker-потоке.
  SQLite и Qt-виджеты используются только из GUI-потока. Результаты привязаны к
  тексту абзаца и поколению личного словаря; старые результаты не применяются
  к изменённому тексту. Кэши ограничены; интенсивный набор не сканирует весь документ.
- Сохранение/экспорт/избранное не обучают модель. Старые неверифицированные
  продолжения сохраняются в БД, но не предлагаются как подтверждённые.
- Настройки модуля, просмотр статистики, исключение формулировок/ошибочных пар,
  резервное копирование, очистка обучения с сохранением первичных личных данных.
- Новые таблицы добавляются без удаления старых. До первого обновления старой БД
  создаётся SQLite backup; личные словари и соответствия сокращений остаются.
- Быстрые строки: категория, правка/удаление пользовательских вариантов, защита
  встроенных строк, нормализованная проверка дубликатов и нечёткий поиск.
- Избранное: обновление из редактора, редактирование категории и поиск содержимого.
- F8 различает языковые и медицинские замечания; добавлены повторы, ограниченные
  правила согласования/пунктуации, отдельных размеров, уровней и отрицаний.
- Форматирование сохраняет методику; однозначные размеры выводятся через латинское x.

## Данные и безопасность

Исходные 497 записей, папки и отображаемые полные источники сохранены.
Аудит проверяет их идентичность до/после отображения. Ранее известные 18 старых
шаблонов без однозначного полного источника по-прежнему требуют проверки врачом;
неполные места не достраиваются предположениями.

В поставку не включается пользовательская SQLite-база или статистика конкретного
врача. Фильтры обучения не являются универсальным деидентификатором: нельзя
импортировать персональные данные пациентов в общие словари и распространяемую
библиотеку. Тестовые строки синтетические. Уточняющие медицинские предупреждения
не устанавливают диагноз и могут как пропустить ошибку, так и потребовать проверки
допустимой записи. Согласование, анафора и сравнение нескольких очагов не решены
полным языковым/клиническим анализом; при неоднозначности правила воздерживаются.

## Измерения

Linux, Python 3.12, CPU, `benchmark_ai.py`, быстрый режим:
- Прогретые коррекции: p95 0,00013 мс; максимум около 0,0013 мс.
- Холодные коррекции двух контрольных слов: 1,5–3,9 мс.
- 100 коротких абзацев, прогретые проверки слов: около 3,5 мс.
- Дополнительный peak RSS теста относительно импортированного приложения:
  около 140 МиБ, включая словарь и библиотеку из 497 протоколов.
- Добавленные бинарные зависимости: 0. Кэш конвертации исходников: около 179 КиБ;
  в EXE попадают восстановленные JSON, как и в прежней схеме сборки.

Эти результаты не являются гарантией для произвольного компьютера или документа.
Точный прирост относительно прежнего EXE не измерен; размер готового ZIP и
Windows-измерения публикуются вместе с отчётом `performance-results.json`.
Предел 150 МиБ желательный, не жёсткий; словарь Spylls — основная часть этой оценки.

## Проверки и сборка

123 автоматических теста прошли на Windows (run 45013746636), включая новые
модульные и Qt-тесты и закрытие окна с отложенным поиском.
Следующий шаг выявил cp1252 в консоли runner: для всех Python-шагов задан UTF-8.
Аудит каталогов — 497/497; отдельно выполнен smoke-сценарий Python-приложения.
Финальный workflow повторяет тесты, аудит, CPU-измерения и **запускает собранный
Windows EXE** с `--smoke-test`. Результаты находятся в ZIP: exe-smoke.json,
layout-audit.json и performance-results.json.

Сбой исходного run 45009817450 вызван квотой Actions artifacts, не ошибкой DOC-конвертера.
Новый детерминированный кэш проверяет SHA-256 канонического JSON исходных DOC-пакетов
(устойчив к LF/CRLF), содержит прежние 128 legacy-записей и 180 полных источников.
Промежуточная загрузка артефакта больше не нужна. При исчерпанной квоте финальный ZIP
публикуется новым prerelease `localai-run<ID>`; старые рабочие сборки не удаляются.
Лицензионные файлы установленных зависимостей копируются в THIRD_PARTY без изменений.
