# Gemma 4 E2B — эксперимент

Функция находится в меню редактора «Локальный ИИ — Gemma 4». При открытии
оба переключателя выключены. Интерфейс запускает локальный llama-server
на 127.0.0.1, по умолчанию с двумя CPU-потоками, контекстом 2048 токенов,
одним слотом и максимум 220 токенами ответа. На Windows процесс запускается
с пониженным приоритетом. Перед запуском проверяется свободная память.
Порог 6 ГиБ является условием запуска, а не жёстким лимитом RSS.
Окно может выгрузить модель. Закрытие окна и три минуты простоя также
останавливают процесс. Изменение документа отменяет текущую генерацию.

## Установка на Windows 10 x64

1. Распакуйте CPU-сборку [llama.cpp](https://github.com/ggml-org/llama.cpp/releases),
   поддерживающую Gemma 4. Оставьте DLL рядом с llama-server.exe.
2. Скачайте `gemma-4-E2B_q4_0-it.gguf` из
   [официальной ревизии Google](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf/tree/675cff42a74c774d6cb76f76d8eacb49b48c9b93).
   Файл занимает 3 349 516 256 байт. Мультимодальный проектор для текста не нужен.
   Файлы можно перенести на рабочий ПК. Карточка модели указывает Apache 2.0,
   лицензия llama.cpp MIT. При распространении файлов сохраняйте их лицензии
   и применимые уведомления. Репозиторий и ZIP редактора не содержат веса Gemma.
3. Укажите оба файла в окне, включите эксперимент и нажмите «Загрузить модель».
   Выделите одну строку описания или заключения, нажмите «Обработать выделенный
   текст». Просмотрите подсветку изменений. Отклонённый проверкой вариант
   отображается для анализа с заблокированным применением.
4. Для фоновой проверки включите второй переключатель. После паузы в 900 мс
   функция рассматривает завершённую пунктуацией строку. Открытая штатная
   подсказка получает приоритет. Запрос привязан к ревизии и хешу исходника.

## Воспроизведение сравнения

На Python из окружения проекта:

```powershell
python -X utf8 tools/benchmark_gemma4.py
python -X utf8 tools/benchmark_gemma4.py --engine C:\llama\llama-server.exe --model C:\models\gemma-4-E2B_q4_0-it.gguf --context 2048 --examples "Контуры чёткие, ровные." > gemma2048.json
```

Повторите с `--context 4096`. A проверяет правила раскрытия сокращений без
пользовательской базы. B запрашивает модель без примеров. C добавляет
переданные проверенные примеры. D берёт прошедший проверку локальный вариант
и обращается к модели для остальных случаев. Для B–D фиксируются загрузка,
RSS после загрузки, пик RSS в ходе теста, CPU процесса, время до первого
выведенного токена, полное время, доступные серверные тайминги и причины
отклонения. Варианты оцениваются на одних искусственных входах. Защищённые
токены выводятся в JSON для проверки. Оценку смысловой корректности и
скорость ввода в редакторе рядом с RadiAnt нужно измерить отдельно на
целевом ПК с обезличенными примерами.

## Полученный результат

Официальный GGUF ревизии `675cff42` загружен из временного тома в RAM.
Движок llama-server build 12631, commit e300919cc, принял модель, обработал
русские запросы через встроенный Jinja-шаблон. Локальный запуск на CPU
с двумя потоками, контекст 2048. Linux x86_64, 3 логических ядра в среде.

| Режим | Ответов | Блокировок проверки | Медиана полного времени | До первого токена | Токенов/с |
|---|---:|---:|---:|---:|---:|
| A. Правила | 5/55 | 0/5 | <1 мс | — | — |
| B. Gemma | 55/55 | 48/55 | 1,286 с | 0,356 с | 18,95 |
| C. Gemma с примером | 55/55 | 45/55 | 1,534 с | 0,409 с | 18,81 |
| D. Правила + Gemma | 55/55 | 45/55 | 1,103 с | 0,088 с | 19,03 |

Загрузка заняла 1,61 с с RAM-тома. RSS после загрузки 4,54 ГБ, пик 4,58 ГБ.
Средняя загрузка процесса 198,7% в шкале psutil, где 100% соответствует
одному логическому CPU. Медианы обработки промпта B/C/D: 354/406/86 мс.
В D пять запросов обслужили правила. Тайминги токенов учитывают только
вызовы модели. Последовательное выполнение B/C/D внутри одной сессии
допускает прогрев и повторное использование префиксов, поэтому различия
задержки нельзя приписывать только наличию примера.

В C использовался один искусственный пример стиля. Разница с B не
показывает эффект реальных личных стандартов. Блокировки включают как
фактические потери, так и консервативное воздержание при отрицаниях.
На пяти контрольных входах модель оставляла сокращения, потеряла первую
компоненту размера 8x6 и исказила «мениск». Некоторые ответы с оставшимися
сокращениями прошли проверку, поэтому допуск не равен удачному раскрытию.
Базовая проверка начала и конца строк не отметила нарушений в основном
прогоне. Она не оценивает полноту русского текста и клиническую точность.
Ответы и причины блокировок записаны в `reports/gemma4-linux-2048.json`
и `reports/gemma4-linux-five.json`.

На Linux прошли 230 тестов. Контекст 4096, целевой Windows 10 с RadiAnt,
задержка GUI при реальной генерации и сравнение с Gemini пока не измерены.
Автоматические оценки используют защищённые токены из входа. Это не
экспертная разметка всех находок и их связей. Защита может пропустить
смысловые изменения вне известных шаблонов.

**Вердикт. Оставить Gemma выключенной в рабочем режиме.** В текущем
эксперименте прирост числа ответов сопровождается слишком частыми
блокировками и неполным раскрытием. Для следующей оценки нужны проверенные
пары врача, независимая разметка фактов и замер на офисном ПК.
