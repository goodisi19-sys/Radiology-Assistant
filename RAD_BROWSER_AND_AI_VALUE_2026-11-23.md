# Google через браузер и проверка пользы локальных моделей

## Изменения

- Правая кнопка в редакторе → проверка выделения либо полного протокола в Google.
  Редактируемый предпросмотр обязателен. Короткий запрос открывается в браузере по
  умолчанию с `udm=50`; длинный целиком копируется, после открытия требуется Ctrl+V.
  Это ручная передача, не интеграция ответов Google в локальные модели.
- Удалены встроенный WebEngine-поиск, автоматическая отправка терминов и парсинг выдачи.
  Существующий подтверждённый словарь не удаляется. Ответы не изменяют документ и
  не записываются в обучение автоматически. Сетевые ограничения/TLS не обходятся.
- Общие контекст и ключ оценок слов; исправлена доставка результата в popup и меню.
  Недописанное слово проверяется отдельно от замены медицинского фрагмента.
  Подсказки вставляются только явным выбором. Числа, стороны, уровни и отрицания защищены.
- Удалена нейроработа без потребителей. RuBERT оставлен для поиска; rerank фраз
  экспериментальный и выключен по умолчанию. SAGE оценивает готовые варианты локально
  в сбалансированном/расширенном профиле при наличии ресурсов; генератор не включён.
- Ручной анализ текущего абзаца доступен в настройках; четырёхсекундная пауза
  автоматического тяжёлого анализа сохранена. Лексические подсказки работают отдельно.

## Проверки исходников, Linux

- `QT_QPA_PLATFORM=offscreen python -m unittest discover -v`: **212 тестов**, 375,230 с, OK.
  Из старых 205 удалены три теста выведенных из программы embedded/TLS-функций;
  добавлены десять тестов нейродоставки/ключей/защиты/таймаута/shortlist.
- `python app.py --smoke-test RESULT`: 497 протоколов, форматирование/DOCX, Tab из
  редактора и popup, Undo, Enter, вставка внутри строки, словарь, избранное, Яндекс,
  локальные модели и контекстное меню Google прошли. Это исходники, не Windows EXE.
- `python app.py --browser-smoke-test RESULT`: Unicode/переносы запроса, полный длинный
  clipboard-путь и отсутствие загруженного WebEngine прошли. Открытие браузера
  перехвачено: проверка реального браузера целевого ПК не заявляется.
- Измерение `benchmark_hybrid_gui.py`: p95 обработки ввода **2,82 мс**, max **8,40 мс**;
  FTS **1,94–5,27 мс**, первичная сборка индекса **4,92 с**; отмена диспетчера **0,41 мс**;
  пик RSS GUI **221,91 МиБ**, worker в этом опыте не запускался, после закрытия детей 0.
  Нагрузка 21,34% одного ядра / 7,11% всей трёхъядерной среды, короткий синтетический
  сценарий 8,11 с. Это не измерение дополнительной памяти моделей и не гарантия CPU за день.

## Качество моделей

Подробная проверка всех 11 пунктов Claude и двух гипотез:
`CLAUDE_AUDIT_2026-11-23.md`. Машиночитаемые данные — `reports/neural-*-value.json`.
Диагностика на старых 24 примерах показывает 16→18 без моделей и 19 с SAGE;
на дополнительных восьми все режимы дают 4/8. Настройка под ответы не выполнялась.
Для RuBERT есть сигнал в семантическом поиске (категория@5 7→13 из 20), но также
ухудшения. Независимая клиническая польза не доказана; нужен отложенный контроль врача
с группировкой дублирующих исходников и фиксированными кандидатами/памятью.

Windows EXE и его время/память оцениваются отдельно в отчётах GitHub Actions данной
сборки. Успех тестов исходников не выдаётся за проверку готового Windows EXE.
