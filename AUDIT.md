# Аудит Radiology Assistant — 12 ноября 2026

## Библиотека

На исходном commit ca4800f свежая SQLite содержит 497 протоколов только после
конвертации legacy DOC: 145 встроенных + 352 дополнительных. Без конвертации — 369.
Теперь CI требует именно 497 записей и 352 дополнительных, а не минимум 245.
Все 497 записей проверяются также в дереве интерфейса и после повторного запуска.

Распределение после исправления метаданных:

| ОМТ | 38 |
| Позвоночник | 90 |

| Всего | 497 |

Приоритет имеет исходная анатомическая папка. Тексты и ID существующих записей
не изменяются. Новые импорты сравниваются по SHA-256 текста с нормализацией
пробельных символов; разные числа, слова и клинические варианты сохраняются.
Существующие повторяющиеся тексты не удаляются при обновлении. Поэтому 497 —
число записей, а не утверждение о 497 уникальных текстах.

В исходных ODT 224 записи и 223 различных текста. Из 180 DOC antiword получает
128 различных пригодных текстов; семь исходных записей не конвертируются
(включая повторные экземпляры): ШОП Норма МЕГИ, ШОП. Норма МЕГИ,
Колено киста мениска МЕГИ, Голеностоп Разрыв Ахилла. Ахиллобурсит Меги.
Их содержание автоматически не восстанавливалось. Конвертер проверяет ожидаемые
числа и завершает сборку ошибкой при отклонении. Эти семь записей не входят
в ранее загруженные 497. Исходные файлы сохранены.

Папки с МИБС и 2006 блокируются при встроенном и ручном импорте, включая ZIP.
Ранее сохранённые пользовательские записи автоматически не удаляются.

## Исправления

- Поиск и автодополнение без учёта регистра кириллицы; исправлен regex префикса.
- Явный приоритет личных верифицированных стандартов независимо от частоты
  обычных фраз; восстановление этого признака из ранее сохранённых стандартов.
- Ошибки встроенного ODT больше не проглатываются.
- Перед миграцией старой базы автоматически создаётся SQLite backup.
  Соединения резервирования закрываются явно: Windows-проверка выявила
  блокировку файла после использования обычного sqlite context manager.
- Открытие, создание и закрытие учитывают отмену и неуспешное сохранение.
- DOCX/TXT записываются через временный файл с атомарной заменой.
- DOCX сохраняет абзацы, пустые строки, полужирный/курсив/подчёркивание и размер
  шрифта редактора; по умолчанию Times New Roman 12 pt.
- При сохранении и экспорте применяется оформление строк по текущему запросу
  пользователя: без начального тире, с заглавной буквой и конечной точкой.
  Внутренние точки с запятой и клинические формулировки сохраняются.
- Исправлена потеря пустых абзацев при оформлении текста; изменения вносятся
  посимвольно с сохранением окружающего форматирования.
- Составные сокращения защищены при оформлении предложений.
- Явные цвета списка автодополнения дополняют цвета главного и дочерних окон.
- Устранено накопление моделей автодополнения при вводе.

## Проверки

18 unittest: библиотека и дерево UI, повторный запуск, SQLite integrity_check,
личные стандарты и backup, запрещённые папки, дубликаты и клинические варианты,
окно строк с поиском и вставкой, DOCX с русским текстом и форматированием,

Дополнительно: check_catalog.py, audit_library.py и запуск приложения
`--smoke-test <result.json>` с изолированной временной базой.
GitHub Actions запускает эти проверки на Windows, собирает EXE и запускает
сам EXE: загрузка 497 протоколов, окно строк, сохранение и чтение DOCX.

## Границы проверки

Проверки UI автоматизированы на Qt offscreen; это не визуальный ручной осмотр
на пользовательском Windows с его DPI и темой. Автоматического медицинского
редактирования и проверки клинической достоверности не выполнялось.
Открытие внешнего DOCX переносит текст и таблицы; полное оформление исходного
Word, изображения, колонтитулы и сложная вёрстка не поддерживаются.
Пути пользовательской базы и существующих данных не изменены; данные на
компьютере пользователя непосредственно недоступны и не проверялись.
